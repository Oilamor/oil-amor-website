# Legacy Hand-Written SQL Migrations — SUPERSEDED, DO NOT RUN

These five hand-written SQL files (`001`–`005`) are the pre-drizzle-kit
migration attempt. They are **archived for historical reference only**.

## Why they must not be run

1. **They conflict with the Drizzle schema** — the running app's source of
   truth (`lib/db/schema.ts`). Examples:
   - `001_initial_schema.sql` defines `forever_bottles` with a UUID primary
     key, `bottle_sku`, `bottle_size`, `total_credits`, `credits_remaining`
     and Shopify `order_id` columns. The Drizzle schema defines the same table
     with a `text` id, `serial_number`, `oil_type`, `capacity`,
     `current_fill_level`, `refill_count` — a completely different shape.
   - `002_refill_system_tables.sql` defines `refill_orders` with UUID id,
     `DECIMAL` price columns and a different status CHECK list; Drizzle uses
     `text` id, a `pricing` jsonb column and the `refill_order_status` enum.
   - `001`'s `audit_logs` is an event log (`event_type`, `actor_type`, …);
     Drizzle's `audit_logs` is an admin change log (`admin_id`, `action`,
     `entity_type`, `entity_id`, `before`, `after`).
   - `001`/`002` create tables nothing in the codebase uses
     (`refill_credits`, `shipments`, `shipment_tracking_events`,
     `customer_sessions`, `synergy_selections`, `webhook_events`,
     `customer_rewards`, `credit_reservations`, `notifications`) and views on
     top of them.
2. **They were never runnable by the migration runner.** There is no
   `meta/_journal.json`, so drizzle-orm's `migrate()` cannot consume them.
3. **They are not idempotent against the real schema.** `001` uses plain
   `CREATE TABLE` (no `IF NOT EXISTS`) for `forever_bottles` — running it on a
   database that already has the Drizzle-shaped table fails; running it *first*
   would have silently created the wrong shape.

## The canonical migration chain

The canonical chain is generated by drizzle-kit from `lib/db/schema.ts` and
lives in [`../../../drizzle/`](../../../drizzle/) with
`drizzle/meta/_journal.json`. Apply it with:

```bash
npx tsx scripts/migrate.ts up        # or: npm run migrate
```

Generate new migrations by editing the Drizzle schema and running:

```bash
npx drizzle-kit generate --name <change_description>
```

See `docs/DB_RECONCILIATION.md` for the full reconciliation report and the
runbook for bringing an existing production database in line.
